# Trust and privacy

Trust is a product feature. Claims must describe actual behavior, not intent.

## Processing labels

Every tool must be classified:

- **Local** — no user payload leaves the browser.
- **Network** — data is sent to a documented non-AI service.
- **AI** — selected data is sent to a named AI provider after consent.

The UI must show the classification before execution for network/AI operations.

## Current state

The current 24 tools are intended to run locally in the browser. Verify this classification whenever a dependency or implementation changes. Vercel Analytics must never receive tool input/output.

Recent history is opt-in and local-only. It stores tool slugs and visit timestamps in IndexedDB, never tool input/output, and retains at most 50 entries. Disabling retention stops new records; Clear history deletes stored entries. If browser storage is unavailable, history remains disabled and fails closed.

Saved workflow recipes are local-only, bounded, and versioned (ADR-023). IndexedDB stores at most 50 definitions containing names, descriptions, initial value types, optional built-in source IDs, engine IDs, JSON-safe options, and timestamps. Every create/update is schema and compatibility validated. Runtime input/output, built-in examples, clipboard content, and execution results are not stored. The workspace provides delete and clear controls and fails closed when storage is unavailable.

Smart input detection is local, deterministic, and ephemeral. The sample stays in component memory, is bounded to 100,000 characters, and is not written to storage, URLs, logs, analytics, or network requests. When a user explicitly opens a suggested tool, the sample may be handed to that tool through a single-use in-memory store (ADR-013); it is still never written to storage, URLs, logs, analytics, or network requests. Confidence is a heuristic and must not be presented as validation.

Workspace export and import are local-only (ADR-014). The exported file contains the workspace format name, schema version, export timestamp, and favorite tool slugs, and it declares `containsUserInputs: false`. Tool inputs, outputs, and history entries are never exported. Imports are validated, size-bounded, filtered to known tools, and merged additively in this browser; nothing is uploaded or fetched.

Recommended next actions are deterministic and local (ADR-015). Suggestions come from a curated registry pairing map plus this browser's favorites and opt-in history slugs, are ranked in memory at render time, and always show a human-readable reason. Nothing new is stored, no tool input or output is read, and nothing is transmitted or generated by a model.

DevHub is installable as a web app, and offline support is served by a local service worker (ADR-016). The worker caches only the app shell — core pages, canonical tool pages, the offline fallback, and static assets — in this browser's Cache Storage. Tool inputs, outputs, favorites, recipes, and history are never written to the offline cache, and the worker introduces no new network path: it only serves cached copies of pages and assets this browser already requested.

Activation and retention measurement is allowlisted and payload-free (ADR-017). The only instrumented events are tool opened, tool run succeeded/failed, favorite added/removed, and command palette opened. Every event passes through the sanitizer in `src/lib/analytics.ts`, which accepts only allowlisted event names, permits a single property — a tool slug validated against the registry — and drops unknown names, unknown slugs, and any extra fields before sending. Events are sent to Vercel Analytics in production builds only; raw input, output, URLs, clipboard content, detector samples, recipe definitions, and history contents are never part of an event.

## Storage rules

- Favorites may store tool slugs in localStorage.
- Do not persist tool input/output by default.
- History defaults off and stores action metadata only.
- Detector samples are never persisted.
- Optional input/output history requires a separate explicit setting and local-only disclosure.
- Workflows and history require a versioned schema, bounded retention, failure handling, and clear-data controls.
- Saved recipe create/update must validate schema and compatibility before writing.
- Exported workspace files must state whether they contain user inputs.
- The offline cache may store pages and static assets only, never tool payloads or recipe records.

## AI requirements

Before adding AI:

1. Name the provider and model.
2. Document exactly which content is sent.
3. Require explicit confirmation for sensitive input.
4. State provider retention implications.
5. Prefer BYOK or local models to keep the free product sustainable.
6. Add per-action cancellation and error handling.
7. Never reuse user content for training without explicit opt-in.

## Copy rules

Allowed when verified:

- “Processed locally in this browser.”
- “No input is sent to our server.”
- “JWT signature is not verified.”

Avoid:

- “Everything is local” when any route uses AI/network services.
- “Secure” without explaining the security property.
- “Private” without a data-flow disclosure.
- Future-dated or invented release history.
- Unverifiable customer or usage claims.

## Analytics rules

Allowed events:

- Tool opened
- Tool run succeeded/failed
- Favorite added/removed
- Workflow saved/re-run
- Command palette opened

Never include:

- Raw input/output
- JWTs, URLs, SQL, hashes, or file names supplied by users
- Clipboard content
- Detector samples
- Recipe definitions or generated recipe content unless anonymized and opt-in
